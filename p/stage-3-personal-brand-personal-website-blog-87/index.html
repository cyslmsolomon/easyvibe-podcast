一、这一集在解决什么问题

个人网页最常见的劝退理由有两个，一是「我不写代码」，二是「搭起来太麻烦」。这一集把两个理由一次拆掉：建站的角色已经从码农变成主编，你定内容和调性，AI 当工程师，平台当地皮；而麻烦的部分，装环境、找模板、拉代码、启服务，全部可以交给 AI 用自然语言驱动。

这一集的完整链路是：三个工具（AI 编辑器、Git、Ruby）→ 注册账号 → 复刻模板 → 拉到本地 → 本地预览 → 推送上线 → 开启 Pages。音频稿按七段展开：

  1. 开场 —— 为什么值得有一块互联网自有领地；
  2. 先认识三个工具 —— 写代码的、运代码的、管本地预览的；
  3. Git 安装与检测 —— 让 AI 检测与安装的最小验收套路；
  4. Ruby 环境安装 —— Windows 四步与 Mac 一键，含输入密码不显示的坑；
  5. 注册账号与起名字 —— 用户名就是网址，门牌号一次想好；
  6. 找模板与拉到本地 —— 复刻、重命名铁律、拿提货单、克隆；
  7. 本地预览与上线 —— 依赖镜像、本地服务、提示词五级加码、推送三连招、开启 Pages。

三、逐节解读

3.1 为什么值得搭：从租借位到自留地

原文给个人主页下的定义是，你在互联网上的一块私有领地。它和朋友圈、知乎这类地方的根本区别是，不依赖任何平台的算法推荐，也不会因为平台倒闭而消失。它通常包含简介、论文、项目和技术博客，是一个长期稳定、可被搜索引擎索引的个人展示空间。

价值可以分三个方向看。对外，它是一张永不过期的名片，申请博士、求职、寻找合作时，一个整理得井井有条的主页远比一份文件简历有说服力。对内，它是第二大脑，课程笔记、技术思考都能沉淀成自己的知识体系。对未来，搜索引擎喜欢结构化内容，别人搜你的名字时，排最前面的是你定义的内容，而不是同名的其他人。三条合起来是一件事，把你在平台上的租借位，变成自己名下的自留地。平台会改推荐规则、会限流、会倒闭，你主页上的一句话，只要服务器还在就在。内容需要时间沉淀，今年写的一篇笔记，三年后就是资历，所以越早搭越划算。

3.2 三个工具与角色转变

搭网页需要三个角色配合，原文的比喻很准。AI 编辑器是坐在旁边的资深程序员，你用自然语言下指令，它写代码、改样式、修错误，你不会语法没关系，看得懂它在改什么就够。Git 是运输代码的快递员，把本地代码打包安全推送到云端仓库，没有它，网站只能在自己电脑上跑。Ruby 环境是懂 Ruby 的翻译官，教程用的学术模板基于 Jekyll 框架，是 Ruby 写的，想本地预览就得先请它进门，你完全不用学怎么写 Ruby，装好就行。

工具链的意义是每一环都让下一环能继续：没有 AI 你写不动，没有 Git 代码出不了电脑，没有 Ruby 连预览都打不开，只能盲改盲传。安装顺序建议先 Git 再 Ruby，因为装 Ruby 工具链时可能还要拉组件，有 Git 更顺。环境装齐再开工，避免做到一半发现少个翻译官，兴致被打断。

更大的转变在角色本身。以前建站你是苦哈哈的码农，现在你是网站主编，决定放什么内容、什么调性；AI 是工程师，把指令变成代码；GitHub 是展示台，免费提供服务器和域名。你要做的不是学会所有工具，而是学会当主编，知道什么是好、什么是对的，然后把活派出去。内容这块没有捷径，AI 能帮你排版，替不了你积累。

3.3 Git 安装与检测

以前装 Git 要去官网下安装包、配环境变量，现在直接让 AI 检测和安装。打开编辑器对话框让它检查，两种情况。情况 A，回复了类似二点几点几的版本号，直接跳过下载。情况 B，命令未找到或一串红色报错，继续往下。没装就继续在对话框输入安装指令，Windows 和 Mac 各有一条，AI 会给一段代码，通常是包管理命令，点代码块右上角的在终端运行，或复制到终端回车，就会自动下载安装。你不需要知道那行命令是什么意思，这就是氛围编程的日常，你说人话，它翻译成机器话，终端只是握手通道。

如果觉得 AI 辅助安装还有不完善的地方，原文给了退路，参考手动下载安装的保姆级教程。两条路都能到。装完必须再检测一次，看到版本号才算数，装过和装好是两回事。这个先问有没有、没有让装、装完报版本的套路，是一次最小化的验收演练，固化下来能少踩九成的环境坑。

3.4 Ruby 环境安装

Ruby 是最后一块拼图。Windows 用户四步。第一步下载安装包，官方有一键包，但直接去官网往往会卡住或失败，强烈建议走国内镜像，版本选自带编译工具链的那个，比如 Ruby 加 Devkit 三点几的六十四位版本，它自带必要工具链，后面少麻烦。第二步执行安装，双击安装包，最关键的勾选是把 Ruby 添加到系统环境变量，漏了这步电脑就找不到刚装的翻译官，后面全盘报错，勾选后一路默认。第三步配置开发套件，进度条走完会自动弹出黑色命令行窗口，不要慌，在光标处输入数字 3，代表安装基础环境和工具链，回车，等代码跑完窗口自动关闭，这是给翻译官配字典。第四步验收，让 AI 检查版本，看到三点几点几即成功。

Mac 用户把检查环境、安装管家、安装 Ruby 三个步骤一次性交办给 AI，它生成带运行按钮的代码块，推进执行即可。新手必看的坑是，安装管家时终端会弹出一行英文要求输入开机密码，Mac 终端输入密码时屏幕不显示任何字符和星号，看起来像没输，这是正常的防偷窥机制，不要慌，盲打完直接回车。很多人以为键盘坏了反复输好几遍。装完同样让 AI 验收。这类环境安装的坑有个共同点，全在验收之前看不出问题，所以每一环都要单独验，别攒着。

3.5 注册账号与起名字

GitHub 是云端仓库兼展示厅，免费托管代码，还能用 Pages 功能把代码变成全球可访问的网址，也是全球最大的代码托管平台，有账号算是技术圈通行证。注册本身不复杂，访问官网、点注册、填邮箱、设强密码、过人机验证、邮箱收验证码。

重点全在用户名。因为主页网址就是用户名加 github 点 io，用户名起什么网址就是什么。建议用英文名拼音、常用编号或简洁字母数字组合，不要起一串乱码。乱码名的链接没法口头告诉别人，印在名片上像钓鱼网站，写在论文致谢里像笔误。用户名是技术圈的门牌号，一次想好，改了代价很大。账号本身也要当资产管，强密码、二次验证、验证码别给任何人；邮箱用自己会看的常用邮箱，GitHub 的通知、合作邀请、仓库告警都走它。

3.6 找模板与拉到本地

网页不用从零写，GitHub 上有成千上万个开源模板，借一个改成自己的名字。教程精选了一个结构清晰、适合学术展示的模板，也列了备选清单，简洁可自用的、灵活多用的、经典两栏博客的、现代扁平风的，各有位置。备选清单的意义不是今天全看一遍，是让你知道路上一直有替换选项，这个用腻了换个骨架接着来。选模板的原则是先跟随教程跑通流程再谈个性化，一上来就挑三拣四容易卡在审美里。模板选的是结构不是皮肤，结构对了换皮肤是几句话的事，结构错了美化半天全是表面功夫，新手看颜色，高手先看骨架。

拿到模板三步。第一步复刻，在模板仓库主页点右上角复刻按钮并确认，相当于把别人的仓库完整复制到自己账号下，你拥有了网站的所有权，注意是所有权不是版权，模板的开源协议该怎么守还怎么守，商用时留一眼协议说明。第二步重命名，最关键的一步，把仓库名改成用户名加 github 点 io，这是 Pages 的铁律，名字不对后续网页打不开。第三步拿提货单，点仓库页面 Code 按钮，选传输安全选项卡，复制以 git 结尾的地址，这是仓库的门牌，建议先粘贴备好。

然后拉到本地。新建文件夹用编辑器打开，在对话框让 AI 把仓库克隆下来。等几秒，左侧目录出现配置文件、首页文件等，说明项目搬到了本地。克隆是快递员的第一单活，从云端把货提回来，提货成功的标志很直观，文件对不上就是网络或权限问题，把现象丢回给 AI。

3.7 本地预览与上线

本地预览两步。第一步装依赖，这种网站需要一堆插件才能跑，直接下载可能卡住，让 AI 切到国内高速镜像再装。第二步启动本地服务，继续让 AI 下指令，终端跑几秒后出现类似本地地址加端口的一行提示，浏览器打开它，网页就出现了。这时候改任何内容，保存刷新就能看到效果，先当样板间把家具摆好，满意了再对外开放。本地预览的大用处是试错成本为零，改坏了关掉服务重来，所有美化都在本地闭环，上线只发验收过的版本。

教程的 Musk 案例，提示词的加码方式特别值得学。第一级定角色和边界，你是这个站点的维护者，每一步只做当前阶段目标，禁止提前做后续内容，不修改站点结构，不引入新插件，身份信息用学术风格模拟，不虚构论文。第二级换身份信息，改姓名、职业、教育背景、研究方向、荣誉。第三级重构出版物数据，改板块标题，建年份文件夹，严格按既有字段格式填内容，不编造新字段。第四级改侧边栏、头像和社交链接，先扫描找配置文件再改。第五级才重写样式，字体、行高、颜色、导航栏、留一点缀色。一级一级来，每级只解决一件事，这就是和 AI 协作改复杂项目的标准姿势，一次性说十件事，它十件都做，十件都得你返工。

上线是标准三连招，初始化本地仓库、添加并提交全部文件、关联远程仓库地址、推送，AI 都会帮你执行，你点运行。推完回仓库页面刷新，代码就在云端了。但网页不会自动生成，要去仓库设置里找到 Pages 选项，部署来源选从分支部署，分支选主分支，文件夹选根目录，保存。保存后网页不会一秒变出来，后台需要大概一两分钟打包、编译、发布到全球服务器。耐心等，刷新，看到上线提示和一串网址，点开它，网站就真的上线了。

五、实践提示

提示1 · 环境安装的最小验收套路

先问有没有，没有让 AI 装，装完让它报版本号。三步一个循环，Git、Ruby、任何未来的环境都适用。装过和装好是两回事，看到版本号才算数。这个套路固化下来，能少踩九成的环境坑。

提示2 · 用户名是门牌号，一次想好

主页网址就是用户名加 github 点 io，乱码名没法口头传播、印上名片像钓鱼网站。用拼音、常用编号或简洁组合，定了就尽量不要改。账号本身也是资产，强密码加二次验证，验证码不给任何人。

提示3 · 选模板选结构，不选皮肤

结构对了，换皮肤是几句话的事；结构错了，美化半天全是表面功夫。第一版先跟随教程跑通流程，个性化是跑通之后的事。备选清单留着，这个用腻了换个骨架接着来。

提示4 · 提示词五级加码，一级只解决一件事

提示5 · 上线只发本地验收过的版本

本地服务就是样板间，改坏了关掉重来，成本为零。所有美化在本地闭环，推送只发验收过的版本。Pages 保存后等一两分钟再刷新，看不到就先等，不要反复改设置。
