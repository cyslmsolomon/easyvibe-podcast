三、再补两个后端选项

火山引擎 Coding Plan（字节跳动旗下云服务平台）——核心优势四条：提供 SLA 保障的企业级稳定性；针对编程任务专门优化；模型选择丰富（Doubao-pro / Doubao-lite 等）；国内节点部署、访问快。接入方式与前文完全一致：注册拿 Key → 写环境变量 → 改请求地址。

其他兼容 Anthropic 的 API——Siliconflow、阿里云 DashScope 等。价值在于多一层选择余地：常用平台限流、涨价或效果不理想时可随时切换，工具本身一行不改。

底层逻辑：协议统一 ⇒ 模型成为可插拔零件。选型方式也随之改变——不再押注单一模型，而是给每类任务分别找最合适的模型。

⚠️ 易忽略点：换了平台，模型名往往也变了。配置时务必以该平台文档给出的模型标识符为准。

四、一个工具管所有模型：路由增强工具

定位：专为 CLI 编程工具设计的智能路由增强工具，按需把请求分发到不同平台的模型，并高度自定义。支持接入几十个平台（OpenRouter、DeepSeek、Ollama、Gemini 等），可按场景路由到特定模型。

原文示例分工：后台批处理交给本地 Ollama（成本近零）；长文本/长代码交给擅长长上下文的模型；代码讲解交给性价比高的模型。

两项附加能力：可视化 UI/CLI 配置管理；通过「转换器（converter）」适配不同平台的 API 格式。也支持自动化集成与自定义扩展。

它解决了什么：一是单一模型覆盖不了所有场景；二是多平台频繁切换很麻烦。装上后只需记住一条启动命令。

演播者的两层延伸：

  1. 成本旋钮——没有它时所有任务走同一模型，贵的一起贵；有了它可以把量大但不重要的任务（批量改格式、写注释）导到最便宜的模型，把架构决策留给最强的模型。同样任务量，账单可能差好几倍。
  2. 容错冗余——某平台抽风时可秒切默认模型到备用平台。对个人开发者，这比省下的钱更重要。

五、路由怎么配：三步走

第一步 · 安装：可交给 AI 助手代劳。装完在终端输入其命令，能看到输出即成功。最常见失败原因是环境变量未生效——记得重启终端。

第二步 · 配置模型来源（两种方式等价，UI 本质上也是改同一个配置文件）：

  1. 点「Add Provider」；
  2. Name 填平台名；
  3. API Full URL 填该平台的兼容接口地址；
  4. API Key 填对应平台的密钥；
  5. Models 区域逐个添加模型名 → Save。

第三步 · 指定默认模型：在 Router 区域把 Default 设为最常用的模型 → Save and Restart。不设默认，工具就不知道往哪发请求。

三条实操经验（演播者补充）：

  1. 备份配置文件——纯文本，存一份到别处，重装后几分钟恢复整套环境；
  2. 先配一个再配第二个——先用两个跑通、确认分发生效，再慢慢加；
  3. 改完必重启——否则改动不生效，会排查半天。

记忆文件（CLAUDE.md）——工具开始对话时自动读取并加入上下文的特殊文件。适合记录：常用命令、核心文件与工具函数、代码风格约定、测试方式、仓库协作规范（分支命名、merge vs rebase）、开发环境配置说明、需要特别注意的坑。

三条编写经验（演播者补充）：

  1. 写约定不写介绍——别介绍项目是做什么的（代码里看得出），要写「这个函数为什么不能改」这类看不出来的东西；
  2. 把踩过的坑写进去——每次因奇怪原因卡住，就加一行原因与结论，半年后它会成为项目最有价值的文档；
  3. 保持简短——超过一屏就没人读，也占上下文；变长了就合并同类项、删过时条目。

另有一个用法：接手别人项目时，先让工具读一遍仓库生成初稿，你再改，比从零写快得多。

七、内部原理：它为什么更好用

核心循环：感知 → 思考 → 行动 → 验证，不断重复。模仿人类开发者的工作流：写代码 → 运行 → 看结果 → 再改进。每一轮可调用不同工具（读写文件、执行命令、搜索代码），并根据工具返回的真实结果决定下一步。

关键差别：它不是一次性写完再交付，而是每步都基于真实执行结果推进——写错就看到报错，看到报错就改。

四大特性

  • 流式处理：一边思考一边输出，不必等全部写完；
  • 智能压缩：长对话把历史压缩成关键信息，区分长短期记忆以减少「遗忘」；
  • 并发控制：内部并行设计让多任务同时进行、互不干扰；
  • 子 Agent 管理：可让多个子 Agent 协作（如一个专测、一个专写文档）。

两条推论（演播者补充）：

  1. 任务描述越具体，循环收敛越快——每轮循环都需要判断依据，说清验收标准，它才知道何时停。
  2. 环境越真实，表现越好——能跑的测试、能访问的数据、能执行的命令，都比口头描述有用。

八、另外两款工具怎么接

Codex（OpenAI 版 CLI 编程工具）——最大优势是对自家最新模型的高效适配；体验上响应更快、犯错率更低，多轮复杂任务一次做对的概率更高。特点：解释偏学术与技术，有时过于严谨、信息量大，初学者可能略难懂。

  • 官方入口：开通订阅或申请配额后，输入启动命令按提示登录即可，配置极简。
  • 第三方转发：在平台购买配额 → 本地配好 Key → 改配置文件里的地址与模型名。注意：密钥分组设置里要选专门用于该工具的那一组。

OpenCode（开源路线）——一条命令安装，可搭配社区配置方案增强。配置是纯文本，可指定默认模型与小任务模型，也可按类别细分：前端/UI 交给一个模型、复杂逻辑与架构决策交给另一个、简单修改与拼写修复交给更轻快的模型。还支持接入外部工具服务（如浏览器调试能力）。

三家怎么选：效果上限 → Codex；生态成熟 → Claude Code；极致灵活与成本控制 → OpenCode。

两条通用提醒：密钥只出现在配置文件或环境变量里，含密钥的文件不应进版本库；每次换模型或改配置后都要跑最小任务验证连通。

十一、实践提示

提示1 · 先写记忆文件，再碰路由

如果时间有限，优先做记忆文件。十分钟写完三条（跑测试的命令、哪些不要动、两条风格约定），之后每次对话都自动生效。路由工具可以等真的需要三个以上模型时再上。

提示2 · 用「同类任务比价」找最便宜的模型

挑一件你最常做的机械任务（如批量写注释），分别在三个候选模型上跑一遍，比较效果与花费。你会很快找出「够用且最便宜」的那一个，然后把它设为这类任务的固定路由目标。

提示3 · 把踩坑记录变成文件的一部分

每次因奇怪原因卡住，就在记忆文件里加一行「现象 + 原因 + 结论」。三个月后这份文件的价值会超过项目里的大部分文档，因为它记录的是别人看不出来的隐性知识。

提示4 · 换模型后必做「最小连通测试」

改完任何配置，立刻跑一个三秒就能完成的小任务确认通了。别等到正式干活才发现接口是坏的——那会让你把接口问题误判成代码问题，白白浪费一小时。

提示5 · 给不可逆操作设一道人工闸门

在提示语里明确写一句：涉及删除、覆盖、格式化之前先列出命令等我确认。这一句话能挡住绝大多数由自动化带来的意外损失。
