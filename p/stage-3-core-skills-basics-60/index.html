三、逐节解读

3.1 斜杠命令：先分类，再记忆

原文列了十二条命令，死记硬背效率很低。按用途分四类，记四组比记十二条容易：

类别命令一句话作用
查询类/help /context /cost看有什么、看占用、看花费
会话类/clear /compact清空重来、压缩续命
任务类/init /plan /diff建配置、先规划、看改动
设置类/config /permissions /model /plugin改配置、管权限、换模型、装插件

演绎方补一个使用节奏建议：开工先 /plan，长对话中盯 /context，每五到六轮 /compact，收工前 /diff 加 /cost。 四个节点一挂，日常管理就闭环了。

3.2 符号系统：混用才是完整形态

四个符号各自独立用都有用，但原文真正想传达的是组合价值。典型组合是「@ 文件 + ! 命令」：先让它读代码，再让它跑验证，它自己看到运行结果，自己判断下一步。

这里有一个认知转折：新手的用法是「你看图传话」，高手的用法是「工具自己看、自己跑、自己验」。 符号组合就是从传话筒过渡到放手的过程。

原文对 & 的说明是后台运行任务。演绎方提醒：后台任务不等于不用管，该看的日志还是要看，否则任务失败了都不知道。

3.3 Token 优化：先诊断，再动手

原文给的是完整策略，演绎方把它整理成「诊断 → 堵漏 → 保养」三层：

  1. 诊断：/context 三个指标，使用率超过百分之七十就要警惕，顺带数引用文件数量、揪出最占地方的大文件；
  2. 堵漏：配好 .claudeignore，把依赖目录、编译产物、日志、图片挡在上下文外；引用从目录级改成文件级；
  3. 保养：每五到六轮对话 /compact 一次；对大文件执行「真的需要吗、能只引一段吗、能拆模块吗」三问。

原文特别强调的一点值得重复：优化 Token 不是不花，是花在刀刃上。 为了省把必要上下文也砍了，判断失准反而更费时间。

3.4 项目背景：CLAUDE.md 是两层体系的第一层

原文的解决方案分自动与手动两层。/init 负责快速起步，人工校对负责质量。校对清单就是原文那四项：项目概述、技术栈、常用命令、代码规范。

演绎方的检验标准：写完之后假装自己是刚接手项目的新人，看能不能照着立刻开工。 能，这份文件就合格了。大型项目用 Rules 目录按主题拆分，本质是同一思路的规模化版本。

第二层是指令里的即时补充。配置文件管长期约定，指令管单次背景，两层别混用——把一次性信息写进配置文件，文件会越滚越长；把长期约定只在指令里说，下次对话又得从头讲。

3.5 回退机制：三条退路，别用错

这是本集风险最高的一节。原文三个场景，演绎方按可靠程度排个序：

场景做法可靠性关键提醒
回退对话作废本轮对话低（不碰文件）只退聊天记录，文件改动原样保留
手动撤销逐文件还原中（会漏）改十个忘九个，漏的就是隐患
Git 预防动手前先提交，改乱就回滚高（可整场还原）提交越勤，回退越精准

「先提交，再放权」这六个字，演绎方建议单独记住。它成本极低，却把最坏情况从「手动收拾残局」降级为「一条命令全部还原」。

3.6 权限系统：三级与三阶段

原文的权限模型只有三个词：allow 自动允许、ask 执行前询问、deny 完全禁止。演绎方的配置原则：读的放宽，写的收紧，删的和推远端的最严。

渐进式三阶段是原文的明确建议：学习阶段保持默认建立直觉，熟悉阶段把查看状态、跑测试这类低风险操作放进 allow，高效阶段再按项目配精细规则。跳级的风险是，你还没建立「它会动什么」的直觉，就放开了它动一切的权限。

演绎方补一条工程实践：权限设置写进项目内的设置文件并随仓库提交，别只放个人全局配置，否则团队成员的边界对不上。

3.7 国内使用：四条路线与三查排错

原文按成本从低到高给了四条路。替代工具表里四款工具的定位原文说得很清楚，一句话版：

  • Cursor —— 基于 V S Code，功能完善，要完整 I D E 体验选它；
  • GitHub Copilot —— 代码补全能力最强，主用补全选它；
  • 通义灵码 —— 国产，国内访问稳定，网络省心选它；
  • Codeium —— 免费额度多，预算有限选它。

排错三查按原文整理：连不上查地址（注意包含版本路径）、查密钥与余额、查本地代理；响应慢换近节点服务商、换编程套餐、/compact 减负；功能缺失先翻服务商文档，第三方兼容未必全支持。

安全底线演绎方再强调一次：密钥不进代码、不进仓库。 泄露的密钥就是别人随便花的钱包。

五、实践提示

提示1 · 命令不用背，按「四个节奏点」挂日常

不要试图记住十二条命令。只挂四个节奏点：开工 /plan 先审计划，聊天中盯 /context 防爆，每五到六轮 /compact 保养，收工 /diff 加 /cost 复盘。四个点形成习惯，命令自然就用熟了。

提示2 · 先诊断再优化，别凭感觉省 Token

觉得贵之前，先用 /context 看一次仪表盘。多数人以为浪费在聊天上，实际大头是引用了一堆用不上的文件。先看数据再动手，.claudeignore 配一次，往往比压缩十次都管用。

提示3 · CLAUDE.md 按「新人能否立刻开工」验收

写完配置文件，做个测试：假装自己是刚接手项目的陌生人，只看这份文件，能不能把项目跑起来。能，合格；不能，缺哪项补哪项。这份文件最大的读者其实是三个月后的你自己。

提示4 · 权限三阶段别跳级，先观察再放权

学习阶段忍住别改配置，先看它默认会动哪些东西、哪些操作会弹窗。有了直觉再放 allow，有了项目理解再配 deny。跳级的代价是，你还没建立边界感，就已经放跑了危险操作。

提示5 · 国内路线按「改动成本」排序试，别一上来就换工具

优先试接口代理（改动最小），再试兼容工具（省配置），都不行再考虑换工具。每换一次环境，都是新的学习成本。让 AI Agent 帮你配置是兜底选项，把完整报错丢给它，比到处翻帖子高效。
