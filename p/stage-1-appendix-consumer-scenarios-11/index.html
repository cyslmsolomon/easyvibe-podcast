stage-1-appendix-consumer-scenarios-11 C 端场景灵感方向参考 · 解读与音频稿件

本稿为音频配套解读，围绕 Easy-Vibe 附录中「C 端场景灵感方向参考」这一整页内容，梳理十六个大类、八十个具体方向背后的共同结构，并给出一套可复用的氛围营造方法与审查清单，帮助你在设计一个面向普通用户的 AI 产品时，先定感觉，再倒推功能。

一、这一集在能力地图上的位置

前面的章节大多在讲「能不能做出来」，这一页讲的是另一半问题：「做出来之后，用户愿不愿意再来」。

在 Easy-Vibe 的整体能力地图里，工程能力决定下限，体验设计决定上限。一个产品可以功能完备、接口优雅、部署顺利，却依然没人用，原因往往就出在它没有回答「用户用完是什么感觉」这个问题。这一页提供的八十个方向，本质上是一份情绪需求样本库，值得反复翻阅，而不是读一遍就放下。

需要提醒的是，这份清单的正确用法不是逐条实现。八十个方向里没有一个是「标准答案」，它们只是别人在满足某种情绪时的具体做法。真正该带走的是它们背后的分类逻辑和营造方法，以及那句反复出现的判断——感觉到位比功能完备更重要。

如果你把这页和前面的工程章节对照着看，会发现一个有意思的张力：工程章节教你把不确定变成确定，这一页却在提醒你，C 端产品的核心价值恰恰留在不确定里。用户说不清自己要什么，但这不代表他没有需求，只代表这个需求需要用感受去接住，而不是用参数去满足。

这也解释了为什么很多技术很强的团队做不好 C 端产品。他们习惯把问题拆清楚、把边界划清楚、把验收标准定死，这套方法在工程上无往不利，但在情绪面前会失效，因为情绪本身就不接受精确定义。你要做的不是把它定义清楚，而是给它留出一个可以被感受到的形状。

所以这一页虽然看起来只是一份方向罗列，真正想传递的其实是一种工作方式的转换：从「我要解决什么问题」转向「我要让人处在什么状态」。前者导向功能，后者导向体验，而这两者的设计流程完全不同。

二、从功能到感受：两种思维的分野

这一页给出的对照非常锋利，值得完整记住：

维度B 端思维C 端思维
效率提高处理效率省下时间去做喜欢的事
成本降低运营成本让每一分钱花得值得
痛点解决具体问题创造一次美好体验
完备性功能齐全感觉到位

这组对照背后是一条判断标准：B 端价值可以被量化，C 端价值只能被感受。

你没法给用户看一张评分表，告诉他这个产品值八十七分。用户只会记住某个瞬间：深夜睡不着时有人回了一句温柔的话，早上醒来看到一句刚好说中自己心情的鼓励，或者在异地旅行时收到一条「这里往左走两百米有家店」。

因此做 C 端产品时，你真正要设计的不是功能路径，而是情绪曲线。功能只是载体，情绪才是产品本身。

一个很实用的自检方法：把你的产品介绍文案拿给一个完全不懂技术的朋友看。如果他问的第一句话是「它能干什么」，说明你还站在 B 端语境里；如果他问的是「用起来什么感觉」，你就已经挪到 C 端这一侧了。

三、十六类方向的能力地图

把八十个方向按底层情绪归拢，会得到一张清晰的地图。

第一类：日常氛围与仪式感。 晨间仪式感唤醒助手、独居生活氛围营造师、周末宅家治愈计划生成器、睡前心灵安抚电台、生活美学灵感捕手。共同点是解决模糊的情绪需求而非明确痛点；用户说不清自己要什么，但用完会觉得舒服。实现上的共同特征是都必须接入上下文——时间、天气、日程、历史偏好。缺了这些，模型再强也只能给出通用的漂亮话。

第二类：情绪陪伴与自我接纳。 深夜树洞倾听者、失恋疗愈陪伴师、焦虑缓解呼吸教练、自信心重建导师、情绪日记智能解读。共同红线是永远不要说教——用户来这里是为了被接住，不是为了被教育。回应的第一句应当先承认情绪的合理性。

第三类：娱乐沉浸与内容共创。 沉浸式剧本杀主持人、开放世界游戏灵魂 NPC、个性化播客生成、虚拟演唱会氛围组、互动小说共创伙伴。判断标准只有一个：参与感。用户是否觉得自己是故事的一部分，而不是在旁观别人写好的内容。工程上最考验记忆与一致性，通常需要额外维护状态。

第四类：成长记录与习惯养成。 个人成长见证者、习惯养成游戏化教练、技能学习搭子匹配、每日小确幸发现者、人生模拟体验器。关键词是被看见——用户需要的不是数据，而是有人见证自己的变化。注意别把激励做成压力，断签清零这类设计会把陪伴变成焦虑。

第五类：社交连接。 破冰话题生成器、朋友圈文案氛围师、约会氛围策划师、远程聚会气氛担当、社交能量管理助手。其中社交能量管理助手尤其值得注意，它服务的是内向者，核心是尊重边界、不要求改变性格。

第六至八类：创意灵感、旅行探索、健康生活。 灵感枯竭急救包、个人风格探索向导、摄影构图氛围指南、城市漫步探索向导、独自旅行陪伴助手、目的地氛围预览、运动动力唤醒师、睡眠质量优化氛围师等。共同点是都不以效率为卖点——灵感急救包不承诺更快出方案，运动唤醒师也不计算卡路里，它们卖的是过程中的状态。

第九至十六类： 知识探索与语言学习、亲密关系与家人关怀、宠物陪伴、消费与理财心态、职业发展、居家空间、一人食与餐桌、穿搭风格。这一组覆盖面广，但底层需求一致，落点都不是效率而是某种具体的情绪状态。

把这张地图再压缩一层，所有方向背后其实只有四种底层需求：被陪伴、被理解、被见证、被取悦。

四、营造氛围的三个层次

这一页给出的方法可以拆成三层，缺任何一层都会导致「好看但记不住」。

感官层负责视觉、听觉、触觉：温暖的颜色、舒缓的声音、流畅的动效。这是最容易做的一层，也是绝大多数产品止步的地方。

情感层负责共鸣与引导：理解用户当下的心情、提供情感支持、创造正向情绪。要做到这一层，产品必须能感知上下文，而不能每次都从零开始生成。

意义层负责认同与归属：让用户感到被理解、产生归属感、给自己的行动赋予意义。这是最难的一层，也是唯一能带来长期留存的一层。

判断是否缺层的办法很简单：问用户「你上次用完这个产品是什么时候、什么心情」，如果答不上来，就说明情感层没建立起来。

把这三层和后面要讲的四类暗示合起来，其实就是一句话：先让用户感到安全，再让用户感到被理解，最后让用户感到自己正在变好。顺序不能颠倒。

五、心理暗示与句式替换规则

贯穿三层的核心手法是心理暗示，原文给了三类句式：

  • 正向暗示：你已经做得很好了，慢慢来没关系。
  • 归属暗示：很多人和你一样，你并不孤单。
  • 成长暗示：每一次尝试都是进步，你在变得更好。

还有一组非常实用的句式替换规则：

  • 不说「你应该……」，改说「你可以……」
  • 不说「你必须……」，改说「如果你想要……」
  • 不说「你还不够……」，改说「你已经……」

这些看起来只是措辞调整，但它决定了产品的姿态是居高临下还是并肩同行。对 C 端产品而言，姿态往往比内容更容易被感知——用户可能记不住你说了什么，但一定会记住你说话时的态度。

建议在产品上线前做一次批量检查：把所有面向用户的文案导出来，逐一搜这三类措辞，有就按替换规则改掉。这是成本最低、见效最快的一次体验优化。

六、审查清单

设计或评审一个 C 端 AI 产品时，可以逐条对照：

  1. 用户用完走出门时，我希望他心里是什么感觉？这个感觉是否被显式写了下来？
  2. 产品是停在感官层，还是建立了情感层与意义层？
  3. 文案里是否存在说教句？第一句回应是否先承认情绪合理性？
  4. 是否存在「你应该」「你必须」这类居高临下的措辞？
  5. 用户是否感到被看见——成长、变化、坚持是否被记录和回应？
  6. 用户是否感到自己是参与者，而不是旁观者？
  7. 激励设计是否变成了压力？断签清零是否会让用户不敢停下来？
  8. 核心卖点是效率，还是过程中的状态？如果是效率，那它其实是个 B 端产品。
  9. 十六类方向里，你的产品对应哪一类？那一类的设计红线你是否守住了？
  10. 情绪曲线是否有低谷兜底——用户最差的那个瞬间，产品如何应对？
  11. 是否接入了足够的上下文？没有时间、天气、历史偏好的产品只能说套话。
  12. 记忆与一致性是否成立？第二次打开时，产品还记得上次发生什么吗？

这十二条不必一次全过。如果你的时间和资源有限，优先守住第 1、第 3 和第 8 条：先写清楚感觉，回应的第一句别讲道理，以及确认你卖的到底是效率还是状态。这三条决定了产品的方向，剩下的九条决定的是完成度。方向错了，完成度再高也没有意义。

七、约束与边界

这一页的方法并非万能，有几条边界需要明确：

第一，情绪需求不等于刚需。 深夜树洞这类方向用户黏性高但付费意愿低，商业化路径与 B 端完全不同，不要拿同一套指标去衡量。用日活去要求一个工具产品，或者用付费率去要求一个陪伴产品，都会得出错误的结论。

第二，陪伴型产品有责任边界。 涉及情绪、焦虑、失恋等话题时，产品不能替代专业心理干预。设计上需要明确能力边界，并在必要时引导用户寻求专业帮助，这是硬约束而非建议。

第三，隐私是陪伴类产品的高压线。 倾听型产品天然会收集大量私密内容，安全感和隐私保护不是加分项而是前提。一旦这条失守，前面所有的氛围营造都会瞬间归零。

第四，游戏化不等于操纵。 习惯养成、储蓄激励这类方向使用游戏化机制时，目标是帮助用户成为想成为的自己，而不是诱导更长时间的使用。判断标准很朴素：用户关掉产品时，是满足还是空虚。

八、如何在 Easy-Vibe 的能力地图里定位你的产品

把这一页和 Easy-Vibe 其他章节串起来，可以得到一个很实用的定位方法。

先在横轴上确认你服务的是组织还是个人，这决定你用 B 端思维还是 C 端思维。再在纵轴上确认你卖的是结果还是过程，这决定你的核心指标是效率还是状态。两个维度交叉，会分出四个象限，而这一页覆盖的是「个人加过程」这一象限。

一旦定位清楚，很多纠结会自然消失。你不会再纠结要不要加强大的批量处理，因为那不是这一象限的用户要的；你也不会再纠结为什么留存数据好看却收不到钱，因为陪伴型产品的商业路径本来就长。

最后提醒一次：这一页给的八十个方向不是八十个选题。真正适合你的可能只有一两个，选多了反而会稀释。产品的力量来自克制，来自你敢于只服务一种情绪，并把那一种做到别人做不到的程度。

九、三个常见误区

把这一页的内容拿去落地时，有三个坑几乎人人都会踩一次。

误区一，把「感觉到位」当成可以后期补的装饰。 很多团队的开发顺序是先跑通功能链路，最后再找人润色文案和视觉。但这一页的逻辑恰好相反：感觉是判据，功能是推导结果。后期补的那些温暖文案，贴在一条本来就不是为这种情绪设计的链路上，会显得格外违和，用户一眼就能看出这是包装而不是设计。

误区二，认为情绪类产品不需要工程能力。 实际上陪伴类产品对工程的要求往往更高：记忆要跨会话保持一致，上下文要实时接入天气和日程，语气要在几十轮对话里不漂移。这些都不是换个提示词就能解决的，需要实打实的状态管理和一致性设计。

误区三，用 B 端的指标去考核 C 端产品。 最常见的错误是用任务完成率去衡量一个树洞产品，或者用打开频次去衡量一个工具产品。指标选错，团队就会朝着错误的方向优化，最后做出一个既不够有用也不够动人的四不像。正确的做法是先回到象限定位，再选那一象限真正该看的指标。

避开这三个误区，这一页的价值才真正能被拿到手。

提示1 · 先写感觉，再倒推功能

打开需求文档准备列功能清单之前，先写下这句话：「用户用完这个功能走出门时，我希望他心里是 ______ 感觉」。把空格填完，再倒推需要哪些功能承载它。顺序错了，后面所有的功能讨论都会失去判据，团队会陷入无休止的优先级争吵。

提示2 · 回应情绪时，第一句不要给建议

陪伴类产品的第一句回应，优先级应该是「承认情绪合理性」，而不是「给出解决方案」。用户来这里是为了被接住。先说「这很正常，换谁都会难受」，再谈下一步，接受度会高出很多。直接甩方案会让人觉得被打发。

提示3 · 用句式替换表批量检查文案

把产品里所有面向用户的文案导出来，逐一检查三类措辞：有没有「你应该」「你必须」「你还不够」。有就按替换规则改掉。这是成本最低、见效最快的一次体验优化，通常一小时就能跑完一轮。

提示4 · 判断一个方向属于哪一类，再找它的红线

选定方向后，先在十六类里定位它属于哪一类，然后把那一类的设计红线抄下来当成约束。比如情绪陪伴类的红线是「不要说教」，娱乐类的红线是「参与感」，成长类的红线是「被看见」，激励类的红线是「别把激励做成压力」。

提示5 · 别把这份清单当选题库

八十个方向不是八十个待实现的选题。正确用法是当镜子：先确定用户此刻处在什么情绪里，再回来找对应方向，看别人是怎么满足这种情绪的。直接照抄一个方向去实现，通常会得到一个没有灵魂的仿品，因为它缺了最重要的那一步——你自己真的处在那个情绪里。

提示6 · 商业化前先想清楚这是陪伴还是工具

陪伴型产品黏性高、付费低，工具型产品付费高、打开频次低。这两条曲线的运营逻辑完全不同。在 Easy-Vibe 的能力地图里，先定位清楚你的产品落在哪一端，再决定指标和商业化路径，否则会一直用错误的尺子量自己，越量越焦虑。

提示7 · 先补上下文，再怪模型不行

如果你的 C 端产品听起来总像在说套话，先别急着换模型。检查一下它有没有拿到时间、天气、日程、历史偏好这些上下文。绝大多数「不够懂我」的抱怨，根因不是模型能力，而是你根本没给它足够的信息去懂。

记住：C 端用户买的不是功能，是感觉；不是工具，是陪伴；不是服务，是理解。

十、一句话收束

如果这一整页只能带走一句话，那就带走这一句：在设计任何面向普通人的 AI 产品之前，先把用户用完之后的那个感觉写下来，然后再倒推需要哪些功能去承载它。

顺序一旦反了，你做出来的会是一个功能齐全、情绪缺位的产品。它会通过所有的测试用例，却通不过用户第二次打开的那一刻。而这一页列出的八十个方向，全部都在提醒同一件事：让人愿意再来一次的东西，从来不是功能清单的长度。
