一、这一集在解决什么问题

前面学过的 AI IDE 与网页版 AI 编程，都是「有界面」的。这一集讲的是另一类：只能在终端里运行的 AI 编程 Agent。

原文开篇就点明了它的定位——与集成在 AI IDE 里的 Agent 相比，这类工具通常上下文窗口更长、工具调用更快、可兼容更多种类的大模型，因此在实战中往往被优先使用。

原文铺了五层内容：

  1. 概念层——CLI 是什么，为什么工业界最常用它；
  2. 对比层——和 AI IDE 的差别，附八项能力对照表；
  3. 产品层——Codex / Claude Code / OpenCode 的定位差异；
  4. 能力层——Claude Code 能做什么、优势在哪；
  5. 成本层——为什么换后端、怎么换，以及 GLM / Kimi K2 / Minimax / DeepSeek 四个选项。

三、先把 CLI 这个概念补上

CLI（Command Line Interface）：通过终端或命令提示符，用纯文本命令操作软件，而不是依赖图形界面（GUI）。Windows 上常见终端是「命令提示符（cmd）」与「PowerShell」，在搜索框输入名字即可启动。

为什么工业界最常用它：

  1. 资源开销——GUI 需要操作系统额外绘制界面、管理窗口；CLI 只需把命令传给系统执行。连接大规模服务器集群时通常只能通过 CLI 交互。
  2. 键盘效率——一部分开发者几乎所有操作都用键盘完成，认为动鼠标反而拖慢效率。

新手最担心的两件事，原文都给了答案：

  • 「命令太多」——照搬前面的思路，让 CLI AI 工具替你执行所有 CLI 操作：进文件夹、搜索处理文件、运行或复制开源项目，全程用对话完成。
  • 「一不小心搞坏电脑」——这类工具执行破坏性操作前通常会先列出命令等待确认。AI 可以干活，最后那下确认得由人来按（演播者补充）。

四、和 AI IDE 有什么不同

两个类比（原文）：

  1. 可以看成一种特殊的对话式助手——只需一个对话入口，自动执行所有操作，只是有时需要自己打开浏览器看效果。
  2. 若类比 AI IDE，则可看作 IDE 中的 Agent 模块（侧边对话区）——只不过被单独拎出来独立运行。

为什么要拎出来：不同 AI IDE 对 Agent 的实现差异很大，能力参差不齐、编程效果不稳定；而 CLI 类工具通常由大型科技公司直接开发（如 Claude 背后的 Anthropic、ChatGPT 背后的 OpenAI），直接使用往往是更优实践。

六、Claude Code 能做什么

定位：Anthropic 基于自家大模型能力开发的 AI 编程工具，主要交互场景在终端，同时支持作为 VS Code 插件使用。

能力面：深度理解代码仓库，用自然语言指令完成端到端任务——代码编辑、修复 Bug、执行并修复测试、管理 Git 工作流（解决合并冲突、创建 PR）、复杂代码讲解、执行终端命令。

四项优势：极长上下文窗口（可处理完整文件甚至小型项目）；主动澄清模糊需求；自动规划与分配执行任务；对整个代码库的深度理解与解释能力。

三个上手场景（演播者补充）：

  1. 接手陌生项目——让它读一遍仓库并生成结构说明，比自己翻目录快十倍；
  2. 批量体力活——按规则批量改名、统一配置格式，人做易错，它做最合适；
  3. 环境配置——把报错原文丢给它，一步步带你走出安装与调试。

费用控制技巧：先从小任务开始（改一个文件、跑一个测试），感受消耗速度，再决定是否上更大的任务。

七、为什么要换后端，怎么换

动机：直接使用官方版本成本往往非常高，因此转而使用兼容协议但基于其他大模型的 API 平台。

两条路径：

  1. 直接使用兼容 Anthropic 接口的 API——GLM、Kimi、DeepSeek、Siliconflow 等均提供兼容接口。推荐先走这条。
  2. Claude Code Route（开源项目）——支持所有常见接口，可按场景精细配置模型，支持对接本地部署的大模型。配置相对复杂。

环境变量（必懂）：一组存在操作系统中的键值对（变量名 = 值），配好之后程序随时可读取。密钥应放在环境变量里而非代码中，以避免泄露。Windows 上它还常用于保存命令行工具的调用路径（PATH）。

⚠️ 原文提醒：若通过 AI 助手配置「永久环境变量」，配置完成后必须重启该工具，否则其内置终端的环境变量不会更新，可能导致登录失败或网络连接错误。

成本参考：这类工具通常消耗大量 token，可用月度套餐（约 20 元/月）控制成本；想先试水可先充值 10 元做小规模试验。

通用接入五步（演播者整理）：注册拿密钥 → 写进环境变量（不进代码）→ 改默认请求地址 → 重启终端/工具 → 跑小任务验证。

十一、实践提示

提示1 · 用「同一个任务、三款工具」做横向评测

挑一个真实的小任务（比如给一个页面加暗色模式），分别在 Codex、Claude Code、OpenCode 上跑一遍，记录耗时、是否需要返工、花费多少。三行数据胜过看十篇测评。

提示2 · 把密钥管理做成一次性动作

第一次配置就把密钥写进系统环境变量，并在代码里统一用 process.env / os.environ 读取。这件事只做一次，之后所有项目都受益，也彻底断掉「不小心提交密钥」的可能。

提示3 · 重启是排错第一动作

环境变量配好了却不生效，八成是没重启工具。遇到登录失败、网络错误、找不到命令这类奇怪问题时，先重启终端或 AI 工具，再排查其他原因，能省掉大量时间。

提示4 · 用「小任务测速」摸清消耗

正式开工前先跑一个最小任务，观察 token 消耗速度与响应延迟。据此估算大任务的开销，再决定要不要上月度套餐。这比事后看账单舒服得多。

提示5 · 换一个界面做一次熟悉的事

挑一件你原本在图形界面里很熟的任务（整理文件夹、改配色），换成在终端里用 AI 工具做一遍。目的不是更快，而是体会「用描述代替操作」这件事带来的变化。
