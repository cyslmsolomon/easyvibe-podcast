三、两个容易被忽略的小服务

邮件服务——原文硬提醒：不要在服务器上自己搭邮件服务器（大概率被判为垃圾邮件）。国内：阿里云邮件推送、腾讯云 SES；海外：AWS SES、SendGrid、Mailgun、Resend。用途：注册验证、通知、营销邮件，均有免费额度。

短信服务——国内：阿里云短信、腾讯云短信；海外：AWS SNS、Twilio。现实约束：国内发短信需企业资质 + 签名备案，个人开发者基本申请不下来。原文建议很实际——个人项目用邮箱验证码替代，别在这上面耗时间。

四、可观测：监控与日志

各家产品：阿里云云监控 + SLS；腾讯云云监控 + CLS；AWS CloudWatch。能力一致：监控 CPU/内存/磁盘、集中收集日志、设置告警规则。

入门替代组合（原文推荐）：PM2 自带进程监控 + Uptime Kuma（开源，一个 Docker 容器即可，支持多渠道通知），个人项目完全够用且零成本。

两条演播者补充：

  1. 监控与日志不可互替——监控回答「现在还活着吗」，日志回答「刚才发生了什么」。只配监控的结果是一挂只知道挂了，不知道为什么。
  2. 告警渠道要选你真会看的——配了邮件通知却一个月不看一次邮箱，等于没配；即时通讯推送的到达率远高于邮件。

判断标准：项目开始有真实用户（哪怕只有十人）就该上最基础的存活监控。

五、对象存储的进阶用法

  • 阿里云 OSS：图片处理（缩略图/水印/格式转换），视频转码需配合 MPS。
  • 腾讯云 COS：数据万象 CI（图片处理 / 内容审核 / 人脸识别）。
  • AWS S3：配合 Lambda 在上传时自动生成缩略图。

原文示例：上传 5MB 原图 photo.jpg，访问时在 URL 后加参数 ?x-oss-process=image/resize,w_300，直接得到 300px 宽缩略图，无需自行处理。

价值：把「图片处理」从工程任务变成一个 URL 参数——省代码，也省存储（同一张图不必存多份尺寸）。

补充两类能力：内容审核（UGC 项目基本必备）、视频转码（自动转网页友好格式与码率）。

成本提醒：媒体处理按调用次数计费，量大时应在前面套一层缓存，避免每次重复计算。

七、三个新手必问的问题

Q1：全用云服务，还是都在 VPS 上自己搭？

阶段建议理由
个人项目 / 学习期VPS 自己搭（Docker Compose 一把梭）省钱，且能学到东西
面向用户的生产项目数据库与对象存储上云，应用层可留在 VPS自动备份、稳定性保障
预算充足 / 团队项目尽量全托管（RDS / Redis / OSS）精力放在业务代码而非运维

Q2：海外免费套餐怎么用？

AWS 新用户 12 个月 Free Tier：EC2 t2/t3.micro 750 小时/月、S3 5GB、RDS 750 小时 + 20GB、Lambda 100 万次请求/月、CloudFront 50GB 出站。

⚠️ 原文警告：到期后自动按标准费率计费，不用了务必销毁资源。强烈建议在 Billing Dashboard → Budgets 设置预算告警。

Q3：国内云和海外云怎么选？

用户在国内 → 国内云 + 备案；用户在海外 → 海外服务；两边都有 → CDN + GeoDNS 分流；不想备案但要国内可访问 → 静态站走 CDN 托管或香港节点（速度不及国内备案机器）。

九、让 AI 帮你部署、排错与加固

两种协作方式

  1. 本地生成脚本，手动执行——让 AI 生成：完整部署步骤清单、全部配置文件（Nginx / PM2 / Dockerfile / docker-compose）、deploy.sh、环境变量检查清单。
  2. AI 直接 SSH 到服务器操作——自动检查环境、装依赖、拉代码、构建、配置、验证。
⚠️ 安全前提：先在测试服务器练手；重要数据定期备份；给 AI 的账号权限最小化（不要给 root）；执行危险命令前先看一眼它要做什么。

AI 辅助排错流程

  1. 先看日志：Nginx 错误日志 / pm2 logs / docker compose logs / journalctl。
  2. 把报错完整复制给 AI，并附上环境、配置、当前状态等上下文。
  3. 对照常见问题速查：
  • 502 Bad Gateway → 后端没启动 / 端口不对 / proxy_pass 地址错
  • 无法访问 IP → 安全组没开端口 / ufw 没放行 / Nginx 没启动
  • 刷新 404 → Nginx 没配 try_files
  • 静态资源 404 → root 路径错 / 文件权限不对
  • HTTPS 证书失败 → 域名没解析 / 80 端口被占
  • PM2 频繁重启 → 代码有 bug，看日志
  • Vercel 函数超时 → 超过 10 秒限制，改长任务平台
  • Railway/Render 503 → 休眠了或额度用完

安全加固清单（可让 AI 生成脚本）：禁用密码登录只用 SSH 密钥；修改 SSH 默认端口；安装 fail2ban；启用自动安全更新 apt install unattended-upgrades；密钥与 .env 不进 Git；定期把数据库备份到对象存储。

十二、实践提示

提示1 · 用「丢数据谁承担」来判断自建还是上云

别问预算多少，问一句：这份数据丢了，后果由谁承担。答案是「只有我自己、可以重来」就自建；答案是「用户」就上云托管。这个判断比价格表可靠得多。

提示2 · 给免费套餐设两个闹钟

第一个闹钟设在到期前一个月，提醒你评估是否续用；第二个设在到期当天，提醒你销毁资源。两个闹钟能挡住绝大多数「月底账单惊喜」。

提示3 · 把速查表贴在编辑器侧边

把「502 / 无法访问 / 刷新 404 / 静态资源 404 / 证书失败 / 频繁重启」这六行和各自的第一嫌疑抄下来，放在随手可见的地方。部署排错时，80% 的情况你会在三十秒内定位。

提示4 · 给 AI 的账号做一次权限演练

新建一个非 root 账号交给 AI，让它执行一次完整部署。如果中途它要求提权，你就知道哪一步需要人工确认。这次演练能在真出事之前，把权限边界摸清楚。

提示5 · 做一次「恢复演练」而不是只做备份

备份做了不等于能用。挑一个周末，把最近的数据库备份真的恢复到一台新机器上，走一遍完整流程。能恢复的备份才叫备份，不能恢复的只是一堆文件。
