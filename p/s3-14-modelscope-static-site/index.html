一、这一集在解决什么问题

网页终于做出来了，接下来当然要找个地方展示，让朋友、同学或者真正的用户可以直接打开它。

两个方向：租服务器自己配域名、HTTPS 和部署流程；或把作品托管到成熟的开源社区，少处理运维工作，把精力留给页面本身。这一集讲第二种——发布到魔搭社区（ModelScope）。

魔搭社区由阿里巴巴联合 CCF 开源发展委员会发起，除 20 万+ 开源模型和 3 万+ 数据集外，也提供用于展示应用的创空间（Studio）。对我们来说它最实用的一点是：不用先成为运维专家，也能给作品准备一个可以免费分享的展示地址。

创空间支持 Gradio / Streamlit / Docker / static 四种类型。本文重点讲 static（已经构建好的纯静态网站）。

一句话概括：创建静态创空间 → 上传构建产物 → 部署 → 通过创空间链接访问。 界面会变，这四步不会变。

原文依据魔搭当前的创空间页面、官方 Skill 与命令行资料整理，最后核验于 2026-08-11。按钮位置可能变化，但主流程不变。

三、逐段拆解

3.1 创空间是什么

魔搭社区由国内大型科技公司联合开源发展委员会发起。创空间支持四种类型：Gradio（机器学习演示应用）、Streamlit（数据应用）、Docker（自定义后端/系统依赖）、static（纯静态网页）。

判断标准一句话：它能不能在没有服务端的情况下，靠浏览器自己跑起来。能，就是静态网页。

主流程四步不变：创建静态创空间 → 上传构建产物 → 部署 → 通过创空间链接访问。

两点补充：

  • 静态档不需要付费硬件，几乎零成本就能拿到长期在线地址。这把试错门槛降到最低——你不需要先说服自己花钱，才敢把东西放出去。
  • 发布这一步有特别的价值：当作品第一次有了可被别人打开的链接，它就从练习变成了作品。而别人打开链接后给的反馈，往往比自己闷头改十次更有用。

3.2 先选对发布方式

你的项目创空间类型发布前要做什么
纯 HTML / CSS / JavaScriptStatic / 静态网页不需要构建，直接准备网页文件
Vue、React、Vite、Svelte 等Static / 静态网页先执行构建，只上传 dist 或 build 里的内容
Gradio 应用Gradio准备 app.py 和 requirements.txt
Streamlit 应用Streamlit准备入口文件和依赖
有自定义后端、系统依赖或特殊启动方式Docker编写 Dockerfile，监听平台要求的端口

红线：不要把 Vue、React 的源代码直接当成 Static 网站上传——浏览器不能替你执行 npm install 和 npm run build。

十秒自检法：打开准备上传的目录，看里面有没有 index.html，且旁边直接跟着样式与脚本文件。如果只有源码目录、配置文件和依赖清单，说明还没构建或进错了目录。

3.3 推荐做法：用官方 Skill 发布

两个相关 Skill：

Skill作用什么时候用
ms-hub魔搭平台统一入口，覆盖仓库、模型、数据集、创空间、MCP 和 Skills Center第一次接入，或只需快捷操作
ms-studio-deploy项目识别、创建空间、Git 同步、部署、日志检查、故障诊断发布或更新本地网页时优先使用

类型判断：根目录已有 index.html 的构建产物会被识别为 static。Static 创空间不负责运行 npm run build，框架项目仍要先本地构建。

安装：先装魔搭 SDK，再装统一入口与创空间部署 Skill。若 modelscope 命令没有 skills 子命令，用官方安装脚本。Skill 默认装到 ~/.agents/skills/。

装完必须重启会话——这个坑表现得很像装失败了：命令显示成功，工具就是找不到。判断方法：装完重启一次，再问工具现在有哪些 Skill 可用。

3.4 用 Skill 发布要准备三样东西

  1. 已安装 ms-studio-deploy Skill，并重新打开过一次智能体会话
  2. 当前目录就是准备发布的目录，且根目录直接包含 index.html
  3. 本机已配置魔搭 Access Token（在终端设置）

纯 HTML 项目直接进网页目录；框架项目先构建再进产物目录（Vite 通常是 dist，Create React App 是 build）。

提示词可以极简——「把当前目录发布到创空间的静态空间」。Skill 会先检查 index.html 与登录信息，需要新建时确认名称与可见性；没有特别说明时建议先用私有空间。

两条底线：

  • 令牌同时用于 API 认证和 Git 推送，不要写进网页源码、README、提示词或可分享截图。
  • 静态网站不需要付费硬件；其他类型的空间若涉及付费资源，Skill 必须先得到你的明确同意。

补一条关于自动化的判断：把发布流程交给智能体，最大的好处不是省时间，而是省力——创建、推送、部署、查日志四件事单独看都不难，但连起来做容易在中间走神导致整条链断掉。交给它，你只需盯住最后那个链接能不能打开。

3.5 手动流程：准备可发布的产物

情况 A：纯 HTML 网页

最小目录就是 index.html + 样式 + 脚本 + 图片，首页文件必须在根目录。

本地检查要在终端起一个本地服务，用浏览器打开 localhost 的 8000 端口——不要只双击 index.html，因为 file:// 和真正的 HTTP 访问在模块、跨域和路径处理上并不相同。双击看着没问题、传上去全崩，是新手最常见的困惑之一。

情况 B：Vue / React / Vite 等项目

先安装依赖并构建，常见输出目录：Vite / Vue+Vite / React+Vite → dist/；Create React App → build/；Vue CLI → dist/。

你要发布的是输出目录里的内容，确保最终仓库根目录直接出现 index.html。

两个只在部署后才暴露的坑：

  • 若 CSS/JS/图片 404，Vite 项目可先把资源基路径改为相对路径，然后重新构建
  • 单页应用建议用 Hash 路由（如 /#/about），因为纯静态托管不一定把所有路径回退到 index.html

建议：构建完不要立刻上传，先在本地起服务把主要子页面都点一遍。多花两分钟，能省掉一轮上传加部署的来回。

3.6 手动流程：创建空间与上传文件

第 1 步，进入创空间并登录。 页面顶部会显示「创建空间 → 搭建应用 → 发布空间 → 分享创意」。未登录时平台会先要求登录或注册。

注意：国内站 modelscope.cn 与国际站 modelscope.ai 的账号、令牌与内容并不互通，面向国内用户通常选国内站。注册前先想清楚用哪个站，换站等于重来一遍。

第 2 步，填写空间基础信息（5 项）：所属账号或组织（决定链接中的拥有者名称）/ 空间名称（建议小写英文字母、数字、连字符）/ 显示名称与简介（访客能看懂）/ 可见性（第一次建议私有，验收后再公开）/ 许可证。

第 3 步，上传网页文件。 进入文件页，上传 index.html、CSS、JS、图片。

高频错误：上传完成后，文件列表根目录必须直接出现 index.html，不能多包一层 dist/、build/ 或项目目录。

为什么会发生：本地构建出的目录名字叫 dist，很多人把整个目录拖进去，于是平台上变成「dist 里再套一层内容」。正确做法是打开这个目录，选中里面全部内容再上传——这一个动作的细节，能挡掉一大半的发布失败。

3.7 手动流程：部署验收与更新

第 4 步，部署设置中选 Static。 平台会提示 Static 适合展示已准备好的 HTML 页面。再次确认根目录有 index.html 后保存。

边界判断：如果网页需要数据库、私密 API Key 或服务端计算，它就不是纯静态网页——应选 Gradio/Streamlit/Docker，或把后端部署到别的服务。把密钥写进前端 JavaScript 无法保密：这不是加密问题，是位置错了。

第 5 步，等待部署并验收。 保存后通常自动开始部署，未触发就手动点部署/重启。等状态变为「运行中」后打开链接，重点确认五件事：

  1. 首页能否打开
  2. CSS、JS 和图片是否正常
  3. 浏览器控制台是否有 404、CORS 或 JS 错误
  4. 手机宽度下是否能正常使用
  5. 复制公开链接后，在未登录窗口中是否仍能访问

最后一条最容易被忽略：私有空间你自己看着正常，不代表别人能打开。

第 6 步，更新。 修改源码后先本地测试并重新构建，回到文件页用新的 dist/build 内容替换旧文件，再重新部署。只上传构建产物，不要上传 node_modules、开发配置和完整源代码。

版本小习惯：每次更新前给旧版本留一份备份。 静态网站回滚不像服务端那样有成熟工具，删掉的文件就是真没了——留一份上一版产物在本地，出问题时能立刻换回去，这比任何排查技巧都管用。

四、约束

约束一：不要把框架源码当静态站上传。 浏览器不能替你执行构建。

约束二：根目录必须直接出现 index.html。 多包一层 dist/ 或 build/ 就打不开。

约束三：不要用双击文件的方式验收。 file:// 与 HTTP 在模块、跨域、路径处理上不同。

约束四：令牌不得出现在源码、README、提示词或可分享截图中。 它同时用于 API 认证与 Git 推送。

约束五：需要数据库、私密 Key 或服务端计算的，不是静态站。 密钥写进前端无法保密。

约束六：第一次发布用私有，验收后再公开，且必须用未登录窗口复验。

五、与 Easy-Vibe 其他章节的关系

在 Easy-Vibe 的脉络里，这一集是整条链路的最后一公里：前面所有「把需求写清楚、把界面做出来」的工作，只有在这一步之后才真正产生外部价值。

和上一集的 PRD 连起来看：上一集决定做什么，这一集决定怎么让人看到。 而这一集反复强调的「先私有、再公开」「用未登录窗口复验」，和上一集讲的「第一版先跑通闭环」是同一种谨慎——先在可控范围内确认正确，再扩大影响面。

还有一点可以迁移到任何发布场景：界面会变，流程不变。 把主流程记成四步，比记住任何一张截图都可靠。

六、审查清单

发布前后逐条打勾：

  • 已确认项目确实是静态站（不依赖服务端计算）
  • 框架项目已在本地完成构建
  • 准备上传的目录里根目录直接包含 index.html
  • 未把 dist / build 目录本身拖进去（只传里面的内容）
  • 未上传 node_modules、开发配置和完整源代码
  • 已在本地起服务（而非双击文件）检查主要页面
  • 若有静态资源 404，已尝试改为相对路径基路径
  • 单页应用已使用 Hash 路由
  • 空间可见性第一次设为私有
  • 令牌未出现在源码、README、提示词或截图中
  • 验收五件事全部通过，包含未登录窗口访问
  • 更新前已备份上一版产物

七、实践提示

提示1 · 十秒自检：看目录里有没有 index.html

打开准备上传的目录——有 index.html 且旁边直接跟着样式和脚本，才说明你拿的是构建产物；只有源码目录和配置文件，说明还没构建或进错了目录。

提示2 · 装完 Skill 一定重启一次会话

不重启的表现和「装失败」一模一样：命令成功，工具找不到。装完重启，再问一次有哪些 Skill 可用。

提示3 · 上传时「打开目录，选中里面全部内容」

把 dist 整个拖进去，根目录就会多包一层，平台找不到入口。这一个动作的细节能挡掉一大半发布失败。

提示4 · 两个坑只在部署后才暴露

静态资源 404（改相对路径基路径）和子页面空白（改 Hash 路由）——本地都试不出来。构建完先在本地起服务把主要子页面点一遍，多花两分钟省一轮来回。

提示5 · 用未登录窗口复验公开链接

私有空间自己看着正常，不代表别人能打开。公开之后一定要在未登录窗口再验一次。

八、收尾

这一集真正想留下的不是某个平台的按钮位置——那些随时会变。而是那四步不会变的主流程：创建静态创空间 → 上传构建产物 → 部署 → 通过链接访问。

以及三条最硬的红线：不传源码、根目录直含 index.html、令牌绝不外泄。

最后那条建议值得照做：第一次发布就用私有，确认页面正常之后再改为公开。 这个顺序看起来多了一步，但它能让你在页面还没调试好的时候，不必担心被别人看到半成品。

而当你的作品第一次有了可以被别人打开的链接，它就从练习变成了作品——别人打开链接之后给你的那句反馈，往往比你自己闷头改十次都更有用。
