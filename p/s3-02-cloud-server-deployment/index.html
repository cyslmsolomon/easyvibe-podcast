一、这一集在解决什么问题

上一集解决了「东西放哪」，这一集解决两个紧接着冒出来的具体问题。

第一，网址从哪来。 服务器给你的是一个 IP 地址——一串没人记得住的数字。要让它变成 yourdomain.com，需要买域名并把它解析到那台机器上。这是从「能访问」到「能被记住」的一步。

第二，控制台里那上百个产品到底是什么。 买完服务器第一次进云厂商控制台，几乎所有人都会懵：ECS、OSS、CDN、RDS、SLB、VPC……每个名字都很专业，每个都像不买不行。原文把这一节命名为「云厂商常见服务功能全解析」，目的就是建立云服务的地图感。

音频稿把这一集的素材重排成了「门牌号 → 算力 → 存文件 → 存数据 → 加速」五段。一句话概括：这一集不教你怎么开通服务，教你怎么判断哪些服务现在还不用开通。

三、门牌号：买域名与解析

买域名：阿里云万网、腾讯云、Namecheap、Cloudflare、GoDaddy 均可。.com 约 55–75 元/年，.cn 约 29 元/年。选名原则是短、好念、无歧义。

解析：在控制台加 A 记录——@ 指向服务器 IP（主域名），www 指向同一 IP，需要后端接口时再加 api。

记录类型作用示例
A域名 → IPv4 地址@ → 123.45.67.89
AAAA域名 → IPv6 地址@ → 2400:xxxx::
CNAME域名 → 另一个域名（配 CDN 必用）static → static.cdn.com
MX邮件服务器（企业邮箱需要）—
TXT任意文本（验证所有权、SPF/DKIM）—

两个高频疑问：解析生效通常几分钟，最长 48 小时，可用 ping 验证；不买域名直接用 IP 也能访问，但对外服务建议买一个。

备案提醒：国内节点绑定域名需 ICP 备案，周期几天到十几天，有上线时间节点时要倒排；海外节点无此步骤。

四、算力组：服务器、函数、容器编排

云服务器——阿里云 ECS、腾讯云 CVM / Lighthouse、华为云 ECS / HECS、AWS EC2。本质是同一件事：可自选配置、自装系统的虚拟机。适用：需掌控运行环境、跑自定义服务、24 小时在线进程。以腾讯云轻量为例：新建 → 选镜像（Ubuntu 22.04）→ 选套餐地域 → 得公网 IP → 重置密码 → 防火墙放行 22/80/443 → SSH 连接。

函数计算——阿里云 FC、腾讯云 SCF、AWS Lambda。上传代码，按调用次数与运行时长付费，无请求不花钱。适用：Webhook 处理、图片压缩、定时任务、流量波动大的 API。不适用：WebSocket Bot 这类常驻服务。

容器编排——阿里云 ACK、腾讯云 TKE、AWS EKS（Kubernetes）。适用：多服务微服务、自动扩缩容、有运维能力的团队。个人/小项目一台 VPS + Docker Compose 足够。

选型判断顺序：只在被触发时才运行 → 函数计算；只有一个服务 → 一台服务器；服务多到需要画拓扑图 → 才考虑容器编排。

附带两块存储：云硬盘（阿里云云盘 / 腾讯云 CBS / AWS EBS）独立于服务器生命周期，机器删了数据还在；共享文件存储（NAS / CFS / EFS）供多台服务器同时挂载，个人项目一般用不上。

五、存储组：对象存储是重点

对象存储——阿里云 OSS、腾讯云 COS、AWS S3。约 ¥0.12/GB/月（标准存储），各家有新用户免费额度（阿里云 5GB 6 个月、腾讯云 50GB 6 个月、AWS 5GB 12 个月）。

用途：用户上传的图片/头像/附件；托管前端静态站（传 dist/ 并开启静态网站托管）；数据库导出文件备份；配合 CDN 加速；生成临时链接分享私有文件。

操作（以阿里云 OSS 为例）：创建 Bucket（名称全局唯一）→ 地域选离服务器近的 → 标准存储 → 读写权限初期选「公共读」，敏感文件选「私有」→ 上传文件 → 拿到形如 https://myapp-images.oss-cn-hangzhou.aliyuncs.com/avatar.jpg 的 URL → 前端直接引用。

原文最重要的两条提醒：

  1. 不要把用户上传的文件存在服务器本地磁盘上——服务器重装/迁移/扩容时极易丢失。
  2. AccessKey 相当于 OSS 密码，绝不硬编码在前端代码或提交到 Git——放在服务端环境变量，泄露后立即到 RAM 控制台禁用旧 Key 并生成新的。

三条实践建议：静态资源与私密文件分桶；图片上传前先在客户端压缩（可省大半存储与流量费）；设置生命周期规则，自动清理或降冷超时文件。

六、数据组：云数据库与缓存

云数据库——阿里云 RDS、腾讯云 TDSQL-C / 云数据库 MySQL、AWS RDS。原文提醒：不要把数据库装在同一台 VPS 上跑生产环境。技术上可行，但生产环境用云数据库可换来自动备份、高可用、监控告警、一键扩容。

创建流程：RDS 控制台创建实例 → 选引擎（MySQL 8.0 最常用）→ 规格（入门 1 核 2G）→ 设置白名单把服务器 IP 加进去（最常卡住的一步）→ 创建账号密码 → 创建数据库名 → 拿连接地址 → 改项目 .env 里的 DATABASE_URL。

迁移临界点（演播者补充）：出现以下任一情况就该迁到云数据库——有注册用户；数据丢失会造成实际损失；需要回滚到某个时间点。

缓存 Redis——阿里云/腾讯云 Redis 版、AWS ElastiCache。用途：缓存热点数据、存 Session/Token、消息队列、排行榜。入门可在 VPS 上 apt install redis-server，生产/高可用场景用云 Redis。

七、加速组：CDN、负载均衡与配套服务

CDN——阿里云 CDN / DCDN、腾讯云 CDN / EdgeOne、AWS CloudFront。把静态资源缓存到边缘节点，用户从最近节点取。适用：有大文件、用户分散各地、想减轻源站带宽压力。Cloudflare Pages 本质上就是 CDN + 静态托管。

配置（以腾讯云 CDN 为例）：添加域名（如 static.yourdomain.com）→ 源站选 COS 源或自有源 → 等 5–10 分钟下发 → 在解析控制台给该域名加 CNAME 指向 CDN 分配的地址。

负载均衡——阿里云 SLB / ALB、腾讯云 CLB、AWS ELB。把流量分发到多台后端服务器并自动摘除故障节点。个人项目一台服务器时用不上。

配套：DNS（万网 / DNSPod / Route 53 / Cloudflare DNS）；SSL（各家免费证书，通用方案是 certbot + Let's Encrypt，90 天自动续期）；VPC（隔离虚拟局域网，新用户一般默认生成）。

顺序原则：用户没抱怨慢 → 不加；抱怨慢 → 先加 CDN（投入最小见效最快）；CDN 扛不住 → 再加机器和负载均衡。反过来就是过度设计。

九、审查清单

  • 已购买域名，并完成 @ / www / 必要的 api 三条 A 记录
  • 已用 ping 验证解析返回的 IP 与服务器一致
  • 国内节点已确认备案流程与时间安排
  • 算力选型已过两问：是否只在触发时运行 / 是否单服务
  • 用户上传文件已走对象存储，未落在服务器本地磁盘
  • AccessKey 存放于服务端环境变量，未出现在前端代码或 Git 历史中
  • 对象存储已设置生命周期规则，静态资源与私密文件已分桶
  • 生产数据库已独立托管，且服务器 IP 已加入白名单
  • 项目配置中的数据库连接串已指向云数据库地址
  • CDN 尚未启用时，未提前配置负载均衡/多机架构
  • HTTPS 已配置，certbot 自动续期已验证可用
  • 已确认不存在「为显得专业而过早上 K8s / NAS」的情况

十、实践提示

提示1 · 用「两问法」给算力选型

先问「是不是只在被触发时才需要运行」——是就用函数计算；再问「是不是只有一个服务」——是就一台服务器。两问之后还不满足，才轮到容器编排。这套顺序能挡住绝大多数过度设计。

提示2 · 做一次「本地磁盘清理」演练

假设你的服务器明天就要重装。列出所有存在本地磁盘上的用户文件，把它们迁到对象存储。这个假设练习比读十遍提醒都管用，因为它逼你真的去找一遍。

提示3 · 给数据库白名单写一条注释

在白名单里加服务器 IP 时，顺手在备注里写清楚「这是哪台机器、什么时候加的」。三个月后你换服务器时会感谢自己——否则你面对的是一堆无标注的 IP。

提示4 · 先看五分钟，不买任何东西

打开云厂商控制台，只看不买。把算力、存储、数据、加速四组各找出一个代表产品，在心里对上号。五分钟就够，但下次进来你不会再发怵。

提示5 · 给「慢」设一个触发阈值

提前定一条规则：当页面加载超过 N 秒、或月度出网流量超过 N GB 时，才启动 CDN 评估。把主观感受变成客观阈值，你就不会因为一次偶然的卡顿而冲动开通服务。
