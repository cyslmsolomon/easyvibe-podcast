参考 UI 设计规范设计页面和按钮 · 从「像谁」到「怎么想」

本内容改编自开源项目 Easy-Vibe，为二次演绎配音版。本篇对应源文档 stage-2/frontend/multi-product-ui/index.md 的「2.1 - 2.5 各家规范 / 4.1 - 4.2 按钮语义 / 6 用 AI 参考规范 / 8 小结」部分，配套音频为本目录下的 stage-2-frontend-multi-product-ui-49-播客.mp3。

一、这篇在讲什么

一句话概括：参考设计规范最重要的不是「做得像谁」，而是学会一套把话说准、把层级排清楚、把按钮分出主次的思考方式。

常见的错误做法是：打开一份规范，看看配色和圆角，照着做一遍。做完发现只是像了皮肤，页面该乱还是乱。

这一节给出的正确角度是：看到一条规范，先问三个问题——

  1. 它定义了什么
  2. 它划了什么边界
  3. 它给了什么判断标准
参考到的不应该只是一个风格，而是一套成熟的设计思考方式。

二、能力地图

完成这一节后，你应该具备：

  1. 概念细分能力：能把「菜单」「下拉框」这类含糊词，拆到「选值还是做动作」「局部还是应用级」「长期显示还是临时展开」的粒度。
  2. 层级建立能力：能用留白、字号、分组建立秩序，而不是靠堆边框。
  3. 结构判断能力：能判断一个页面是浏览型还是任务型，是阅读、选择还是提交。
  4. 按钮分级能力：掌握五种按钮角色，以及「一个区域只留一个主按钮」的纪律。
  5. 系统化能力：理解设计令牌与统一规则的价值，能让多个页面保持结构语言一致。
  6. 提示词迁移能力：知道把规范原文关键句直接贴给人工智能，比自己总结一大段更有效。

提示一 · 概念细分影响的其实是三件事

Apple 把「菜单」继续拆成五种，这个区分会直接决定：

维度选项 A选项 B
这个组件拿来干什么选一个值做一个动作
它属于哪一层页面局部整个应用
它怎么呈现长期显示当前选中值只在点开时临时展开命令

这三件事只要有一件搞反了，用户用起来就会觉得别扭，但又说不出哪里别扭。

真实场景：你说「这里加个下拉框」，同事可能做出一个点开选值、选完显示当前值的控件，也可能做出一个点开就执行命令的控件。两个都叫下拉框，但用户点下去的期待完全不同——前者选错了可以再选，后者一点就生效，反悔都来不及。

为什么后台类界面更要把层级做狠

Fluent 2 特别适合后台、工具型产品和复杂表单系统，原因值得单独点出来。这类界面的特点是信息密度高、操作多、用户一待就是几个小时。

在这种场景里，一个按钮的视觉重量错一点点，累积起来就是巨大的疲劳。用户一天要点几百次，每一次都要先看清哪个是主要的，这个成本会成倍放大。

越是工具型的界面，越要把按钮层级做得斩钉截铁。宁可显得朴素，也不要让用户在每次点击前犹豫。

提示二 · 稳定重复 vs 响应上下文

Material 帮你明确「哪些元素应该稳定重复，哪些应该响应上下文变化」：

类型应该包含原因
稳定重复导航、页面标题、主要操作区用户在任何页面都能在熟悉位置找到
响应上下文内容区、提示信息、推荐位它们跟着当前任务走

如果把这两类搞反（例如让导航跟着内容变），用户每翻一页就要重新找入口。

四、按钮：先分语义，再分样式

核心原则：不要先想「蓝色按钮还是黑色按钮」，先想这个按钮是什么角色。

按钮类型作用常见样式策略
Primary当前区域最关键动作实心、高对比、最显眼
Secondary支持性动作描边或低一级强调
Tertiary / Text弱操作文字或低视觉占比
Destructive删除、停用、清空等风险操作警示色或明确风险样式
Icon button局部工具操作简洁、靠近上下文

提示三 · 四个主按钮等于没有主按钮

这是新手最容易踩的坑。

如果页面上有 4 个主按钮，那么等于没有主按钮。主按钮的意义本来就是「告诉用户现在最应该做什么」。

共同做法：

  • 一个主要区域通常只保留一个主按钮
  • 取消、返回、关闭一般不和确认按钮抢同级
  • 更多操作放到次级按钮或菜单中

提示四 · 危险操作：颜色是提示，确认才是刹车

删除、停用、清空这类操作，除了要有警示色，最好还要有一次确认。

判断标准：凡是后果不可逆、或者影响范围超出当前页面的操作，都值得加一道确认。

觉得多一次确认麻烦的想法，忽略了一个事实——这类操作一旦误触，找回来的成本比多点一下高得多。

五、让人工智能参考规范的正确姿势

错误做法

「帮我设计一个好看的页面」（再加几个形容词）

这类提示词太模糊，人工智能最后通常只能模仿「白底、圆角、阴影」这三板斧，做出来千篇一律。

正确做法：直接贴规范原文的关键句

两个好处：

  1. 你不用自己先「翻译」一遍设计思想——翻译这一步本来就是最容易走样的
  2. 人工智能更容易按官方定义去理解页面和按钮——而不是按训练数据里的平均值去理解

组合用法

一次贴两句原文，让人工智能同时参考页面规范和按钮规范：

  • 一句讲「建立清晰的视觉层级」
  • 一句讲「一个布局里只用一个主按钮」

然后再加上你自己的两句需求。

这种方式特别适合新手，因为你只要会复制原文，再加两句自己的需求就够了。

六、审查清单

  • 描述界面时是否用了准确的概念，而不是「菜单」「下拉框」这类含糊词？
  • 每个「选值类」组件是否明确了它是选值还是触发动作？
  • 首屏是否只聚焦一件事，而不是平铺五个卖点？
  • 秩序是靠留白 / 字号 / 分组建立的，还是靠堆边框？
  • 是否判断过页面是浏览型还是任务型？是阅读、选择还是提交？
  • 导航 / 标题 / 主操作区是否稳定重复？
  • 每个主要区域是否只有一个主按钮？
  • 取消、返回、关闭是否与确认按钮同級？
  • 危险操作是否有警示色 + 一次确认？
  • 按钮尺寸、颜色、圆角、间距是否有统一规则（设计令牌）？
  • 让人工智能参考规范时，是贴了原文关键句，还是只给了形容词？
  • 参考的是规则与结构，还是只抄了皮肤与结果？

落地练习 · 三分钟改造一个页面

找你自己做过的一个页面，按顺序做三件事，每件事不超过一分钟：

  1. 圈主按钮：数一数页面上有几个实心高对比按钮。如果超过一个，取消掉多余的，把次要动作改成描边或文字按钮。
  2. 查含糊词：翻一遍你的需求描述，把「菜单」「下拉框」「弹窗」这类词，改成「点开选值」或「点开执行」的明确说法。
  3. 补一次确认：找出页面上后果不可逆的那个操作，加一道确认。

三件事做完，页面的可懂度通常会有肉眼可见的提升，而你没有写一行样式代码。这正是「先分语义再分样式」的威力。

八、能力自测

不用真的重做页面，用下面五个问题检验：

  1. 同事说「这里加个下拉框」，你会追问哪三个问题来确定他到底想要什么？
  2. 一个页面上有四个实心高对比按钮，用户会遇到什么困难？该怎么改？
  3. 删除操作除了换颜色，还应该加什么？判断标准是什么？
  4. 为什么导航应该稳定重复，而推荐位应该响应上下文？
  5. 让人工智能参考规范时，贴原文和自己总结，哪种更稳？为什么？

能答上三个以上，说明「定义 → 边界 → 判断标准」这套角度你已经建立了。

十一、时间不够时怎么砍

优先级项目理由
必做一个区域只留一个主按钮投入最小、见效最快
必做危险操作加一次确认省下的返工成本远大于投入
必做把含糊词换成准确说法直接决定人工智能生成质量
可后置建立完整的设计令牌体系单人小项目收益有限
可后置逐条读完各家规范带着问题查比通读有效
可简化五种按钮角色降到三种主、次、危险三档已能覆盖多数场景

十二、这条思路还能用在哪

「先分语义，再分样式」不只适用于按钮：

  • 写文档：先分清这段是在说明事实还是在给出建议，再决定语气和版式。
  • 设计接口：先分清这个调用是查询还是写入，再决定命名与错误处理。
  • 排任务：先分清这件事是阻塞性的还是可并行的，再决定排期。

共同点是：在被问「做成什么样」之前，先回答「它是什么」。 顺序反了，后面所有的打磨都是在错误的地基上刷墙。
